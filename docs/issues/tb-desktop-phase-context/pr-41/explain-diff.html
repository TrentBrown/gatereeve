Background

The broad model: observation and governance are separate

GateReeve Desktop reads a canonical workflow snapshot. The pinned state machine says which phase is current, while the user may select another state for historical inspection. That distinction is load-bearing: looking at Designing must never move a feature back to Designing.

Canonical snapshotState, artifacts, statuses, safety
Presentation helpersRead-only view models
Renderer DOMInspection and artifact opening

Before PR 41, selecting Designing, Specifying, or Planning mainly changed the selected rail node, milestones, and primary artifact. The space below the rail had little to say about how those phases transform context.

The narrow model: artifacts have identity, sources do not pretend to be files

Workflow artifacts such as spec.md already have canonical IDs and safety metadata in the snapshot. Living inputs such as the existing codebase or repository structure do not. The new surface preserves that difference instead of making every chip look clickable.

Key invariant: an artifact path is display text, never authority. Opening still uses the canonical artifact object supplied by the snapshot.

Intuition

Think of each phase as a small transformation card: the left side answers “what does this phase read?” and the right side answers “what durable artifact does it produce?” The card follows the state selected for inspection, not the actual governed state.

Code walkthrough

1. Encode recipes

PHASE_CONTEXTS freezes the exact three contracts. The helper returns null for Implementing, Finalizing, and Complete, so unsupported states cannot leak stale content.

2. Resolve safely

phaseContext() builds an ID map from snapshot.artifacts. Missing inventory becomes an unavailable disabled entry; unsafe metadata also disables opening.

3. Render semantics

Living sources become inert span elements. Artifacts become native buttons with filename, status, explicit accessible names, and the existing openArtifact() route.

4. Fit the workspace

A container query keeps Uses and Produces in two columns when possible and stacks them below 720px of actual card width—not merely viewport width.

5. Reuse visual language

Status text receives GateReeve's existing .status plus normalized status class. Present is green, Changed/Pending amber, and Missing/Stale red.

6. Prove boundaries

Tests assert exact recipes, selected/current independence, inspector behavior, missing/unsafe handling, hiding, semantic labels, responsive CSS, and colored status wiring.

A representative safety path

const artifact = artifacts.get(entry.id) ?? null;
return {
  artifact,
  status: artifact?.status ?? 'unavailable',
  disabled: artifact === null || artifact.unsafe === true,
};

This makes the failure mode honest. A known pending artifact may still open the existing unavailable presentation; an unknown or unsafe artifact cannot become an accidental file-system capability.
