Background

The beginner's model: release as chain of custody

A signed macOS release is more than a build. GateReeve first constructs Plugin and Desktop candidates from one immutable source. A protected Apple job signs and notarizes a universal DMG. Native Apple Silicon and Intel runners independently verify it. A read-only finalizer then seals a publication plan. Only a separately approved publication job may mutate public surfaces.

PrepareComplete Plugin tree and universal DMG
TrustSign, notarize, staple, Gatekeeper
VerifyNative ARM64 and Intel evidence
SealExact source, bytes, and plan digest
PublishFive ordered public receipts

The important invariant is exact-byte authority: later stages may consume verified retained bytes, but they may not rebuild or silently substitute them.

The immediate history

RC.5 revealed a transport defect: hidden Plugin files could be omitted even though required visible files remained. PR #44 corrected the transport and verifier. RC.6 then exercised the corrected lifecycle for real from source 10a726411fd46f58263f8c989ac83f1a65bdf33f.

Product topology stays local. GateReeve continues to publish one universal DMG and coordinated Plugin/Desktop surfaces. This conformance work does not import PortReeve's architecture-specific DMGs, CLI matrix, or native service.

Intuition

Think of the sealed plan as a shipping manifest. Each public destination signs a receipt for the same cargo. If delivery stops after the third destination, recovery does not repack the cargo or erase the first receipts. It verifies those receipts and resumes at destination four.

1. Tagv0.1.0-rc.6
2. Plugin4a204590…
3. ReleaseExact DMG + checksums
4. ManifestFirst attempt: HTTP 403
5. WebsiteWaiting on manifest

The repository setting that permits Actions to create pull requests was enabled while default workflow permissions stayed read-only. A fresh protected recovery dispatch then verified and skipped steps one through three, merged deterministic one-file PR #45 for step four, and verified the Early Access response for step five.

Recovery was not a generic rerun. It was bound to the same finalization run, source, tag, plan digest, approver, retained bytes, and earlier receipts.
