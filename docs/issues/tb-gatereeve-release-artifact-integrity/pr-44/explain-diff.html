Background

RC.5 proved the bytes were trusted, but not that every Plugin byte arrived

What failed

The Plugin marketplace was uploaded as a directory. GitHub artifact transport omitted dot-prefixed files. The resulting 309-file tree no longer contained the catalogs, package manifests, and build provenance that made the candidate complete.

What worked

Remote publication verification rejected the incomplete deployment before the Desktop GitHub release and later surfaces were published. RC.5 remains immutable evidence; the mutable marketplace branch was restored to verified RC.2.

Recovery rule: RC.5 is not retried, repaired, deleted, or retargeted. This code supports a fresh RC.6 through the complete protected lifecycle.

Intuition

A tamper-evident chain of custody for one directory tree

The integrity manifest lives beside the marketplace, never inside it. It records every safe regular-file path, byte count, SHA-256 digest, and a deterministic aggregate tree digest. It is the producer's commitment to the exact publishable tree.

1 · ComposeBuild the Plugin marketplace exactly once.
2 · CommitWrite external integrity.json over every file.
3 · Round-tripUpload with hidden files, download, and verify.
4 · TrustOnly then allow signing, notarization, and native evidence.
5 · PublishReverify retained bytes before every public mutation.

There are two independent protections: byte identity catches missing, extra, or modified files; semantic validation catches a self-consistent but malformed marketplace. Passing one never substitutes for passing the other.

1. Deterministic full-tree commitment

plugin-candidate-integrity.js inventories only safe regular files. It rejects traversal, duplicates, unsorted records, symlinks, special files, unexpected additions, omissions, and byte mutations.

marketplace/
  .claude-plugin/marketplace.json   bytes + sha256
  .cursor-plugin/marketplace.json   bytes + sha256
  hooks/hooks.json                  bytes + sha256
  skills/...                        bytes + sha256
  RELEASE                           bytes + sha256

integrity.json                      external manifest + tree digest

2. Fail-closed command and record boundaries

The CLI can produce and verify the commitment. Hosted finalization requires it. Trusted-lifecycle and coordinated-release records carry its identity, and schema-v2 publication cross-checks the original manifest against both records.

prepare --integrity-manifest <path>
verify-plugin-integrity --marketplace <dir> --manifest <path>
finalize-hosted --plugin-integrity <path>   # required

3. Transport proof before Apple authority

The preparation workflow uploads a narrow wrapper directory containing marketplace/ and integrity.json, with hidden-file inclusion explicit. A read-only round-trip job downloads and verifies it; desktop-trust and trusted assembly depend on that result.

coordinated-plugin-candidate/
├── marketplace/
└── integrity.json

prepare → plugin-candidate-round-trip → desktop-trust → finalization

4. Regression and operational contracts

Tests cover missing hidden and visible files, extra files, byte mutation, malformed and self-consistent semantic incompleteness, symlinks, evidence placed inside the tree, CLI round-trips, packet mutation, and workflow dependency ordering.

What this correction deliberately does not alter

Product shape

GateReeve keeps its universal macOS DMG and coordinated Plugin/Desktop release graph. No PortReeve CLI or native-service topology is imported.

Authority

release-trust and release-publication remain separate. This change neither reads nor rotates secrets and grants no publication authority.

History

RC.5 and its Apple request history remain immutable. The next candidate is RC.6, built only after this correction reaches main.

Remaining proof

Actual GitHub artifact transport, protected Apple work, public RC.6 deployment, and Mac/Homebrew installation are later governed steps—not claims made by this PR.
