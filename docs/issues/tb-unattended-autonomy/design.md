# Design - tb-unattended-autonomy

**Status:** draft

## Problem

The highest autonomy level, `autonomous`, still stops to ask the human. Three
sources cause this:

1. The planning backbone always interviews the human. WORKFLOW.md says
   "interview the user", and grill-me says "ask ONE question... wait". Neither
   has an autonomy branch.
2. Start-up questions: full or light, and a workspace feature mismatch.
3. Turn endings. The agent ends while CI is pending, or ends on "shall I
   continue?", and nothing wakes it.

The human wants to grant a run and come back to a pull request: see how
things turned out, including what the agent decided on their behalf. They
still want a mode that may ask useful questions.

## Intent

Add a top autonomy level, `goal`, that runs from the grant to a pull request
without asking. It keeps every GateReeve proof obligation and the per-PR human
release merge. Every choice the agent would have asked about is recorded,
reviewed independently and shown on the PR.

## Chosen shape

**Dial.** `autonomy: supervised | delegated | autonomous | goal` (D1). `goal` has
exactly `autonomous` authority: a fixed named-run human mandate
`{goal, constraints}`, release-branch protection, `autonomous-evaluator`
planning decisions, residual-risk adjudication, and in-mandate amendments
without hand-back. It adds the four behaviors below. Defaults stay
`full`/`supervised`. Only a human grants `goal`.

**Grant (D5).**
- A new `/goal <objective>` skill does all the attended work while the human
  is present. It:
  - checks prerequisites and reports any failure to the human immediately:
    release protection, a usable workspace configuration, an available second
    review provider;
  - takes rigor `full` unless the human said light;
  - takes the constraints;
  - creates a topic branch from the fresh default branch and replaces or
    writes the workspace configuration under the grant's authority;
  - records the mandate and starts the run;
  - arms the native goal.
- A plain-language grant ("goal mode: ...") is also recognized.
- An existing run can be raised to `goal` with `run.set-dial` and a mandate.

**One decision record (D6, D10).**
- There is one interview procedure and one record for both modes.
- Each `interview.md` entry carries **Answered by:** `human | agent`. Agent
  entries also record the options considered and whether the choice can be
  undone.
- Decisions made after design use the existing `scratchpad.md` /
  `decisions.md` records with the same field.
- grill-me has a mode switch. Under `supervised`, `delegated` and
  `autonomous` it asks the human. Under `goal` it answers itself and tags the
  entry `agent`. Either way it continues from wherever the record ends.
- There is no separate assumption store or operation. Planning approval pins
  `interview.md` by hash together with `design.md`, so a changed record is a
  changed subject.
- Independent planning and boundary reviewers assess `agent` entries against
  the mandate.
- `review.publish` writes a "Decisions made for you" section into the PR, built
  from the `agent` entries. `status`, the CLI and the desktop show the same
  entries.

**No-ask (D3).** The PreToolUse hook denies the harness question tools under
`goal` (Claude Code `AskUserQuestion`, Codex `request_user_input`). Its denial
tells the agent to answer the question itself and record an `agent` entry. It
admits the tools only after a recorded park.

**Switching modes mid-run (D5, D10).**
- **Human interview, then goal, before design approval.** The run is raised
  with `run.set-dial autonomy goal` and a mandate. The agent continues the
  same interview as `agent` entries, synthesizes `design.md`, and approves it
  with `autonomous-evaluator` authority.
- **Human interview, then goal, after design approval.** The agent continues
  from the current phase. Nothing is repeated.
- **Goal, then the human returns.** The run is set back to `supervised`. The
  human reviews the `agent` entries and either confirms one (provenance
  becomes `human`) or overrides it with a superseding human entry. After
  approval, an override goes through the normal amendment path.

**Persistence (D4).**
- On the grant, the agent arms the harness goal (Claude Code `set_goal`,
  Codex `create_goal`). The goal condition is generated by GateReeve and bound
  to its own state: "`status` for run X reports a ready final PR, or a
  recorded park".
- `status` exposes that terminal state as a machine-readable field for the
  evaluator.
- SessionStart in a `goal` run tells the agent to check and re-arm the goal
  after a restart or compaction.
- On harnesses without a native goal, a GateReeve Stop hook blocks stopping
  until the same terminal state holds.
- While CI or review bots are pending, the agent waits with a PR watcher
  instead of ending its turn.

**Blockers (D2, D8).**
- Blockers include: a missing second review provider, a check that cannot be
  proved, credentials or production access, a needed mandate change, lost
  protection, and a harness usage limit while the agent can still act.
- On a blocker, the agent first advances as far as it can and opens a draft
  PR that lists the unmet gates and blockers.
- It then records a park, pauses the native goal and asks through the harness
  question tool with full context.
- A blocker never bypasses a protection or changes the mandate.
- No budget field is added.

**Testing permission (D7).** The grant covers the test methods needed to
prove the change, even where project files say to ask first: running the app,
simulators/devices, browser automation and screenshots. The PR lists each
method used. Rules on how to test still apply. Production, data deletion and
harness/system approval prompts are excluded.

**Endpoint (D9).** Success is a ready final PR: mandatory proof qualified,
both reviews complete, summary and decisions published, PR open and unmerged.
The release merge still needs "merge #N", and deployment remains separately
authorized.

## Alternatives considered

- **Name it `unattended`.** Rejected: "unattended authority" already means
  delegated + autonomous (`adapter.js`).
- **A flag on `autonomous`, or redefining `autonomous`.** Rejected: the human
  values a mode that may still ask, and wants a single ladder.
- **Park at a blocker with no PR, or never stop.** Rejected in favor of
  always delivering a PR to inspect.
- **Instructions-only no-ask.** Rejected: prose drifts. A hook is
  deterministic for the question tools.
- **The human types `/goal`, or a Stop hook only.** Rejected: nothing would be
  armed automatically, and the harness pause/resume/stall UX would be lost.
  The Stop hook stays as the fallback.
- **Assumptions in docs only, without review.** Rejected: they would be
  unreviewed and invisible to the protocol and desktop.
- **A separate `assumption.record` protocol store next to `interview.md`.**
  Rejected (D10): it duplicates decisions and makes a human interview
  followed by a switch to `goal` awkward.
- **Merge the final PR (tstack full-send), or require a budget.** Both
  rejected.

## Constraints

- No proof obligation, review pair, protection or mandate check is weakened.
  Autonomous judgment still cannot waive mandatory facts.
- Defaults are unchanged, and no configuration enables `goal`.
- Current/8 records stay valid. Adding a dial value must not reinterpret
  existing runs.
- The plugin ships to both Claude Code and Codex from `plugin-src/`. Hook
  manifests, skills and the desktop resource copies must stay consistent with
  the platform contracts.
- The native goal APIs are optional capabilities. GateReeve must work, through
  the Stop-hook fallback, where they are absent.

## Open risks

- The native goal tool names and behavior were observed from installed
  binaries (Claude Code 2.1.330, Codex 0.171.0), not documentation, and may
  change between versions.
- Codex PreToolUse matching of `request_user_input` is unverified. If it
  cannot be matched, enforcement on Codex is instructions-only.
- Asking in a plain message cannot be blocked, only discouraged. The goal
  evaluator and the Stop hook make such a turn ending non-terminal.
- Resuming a parked run (an answer through the question tool, or a new human
  message) is to be specified in the spec.
- The reviewed `agent` entries live in a file the agent can edit. This is
  mitigated by pinning the interview record's hash into the planning subject,
  which is the existing rule for `design.md` and `brief.md`.
- Self-interviewed designs may drift from intent. This is mitigated by
  mandate-compliance and assumption assessment in independent review.

## Changes

### 2026-11-21 - Rename `autonomous` to `mandated` (interview D11)

The level formerly called `autonomous` is renamed `mandated`, so the dial
reads `autonomy: supervised | delegated | mandated | goal`. Wherever this
design says `autonomous` as a dial value, read `mandated`. The property and
`run.set-dial` dial name stay `autonomy`. Retained events and requests carrying
`autonomous` remain valid: they are accepted and read as `mandated`. The
`autonomous-evaluator` authority kind and "autonomous authority" as the shared
term for `mandated` and `goal` are unchanged. Human approval: "Level ->
`mandated` (Recommended)", 2026-11-21.

### 2026-11-21 - Planning-review clarifications (spec A3)

These follow the independent planning review of the amended spec. They are
within this design:
- Codex was observed to support Stop hooks, so the Stop hook is registered
  on both platforms and is the persistence floor everywhere. The native goal
  is armed where available.
- The Stop hook has a bounded stall valve: it admits the stop after 3
  consecutive blocks with no new protocol event, so a stuck agent cannot loop
  without limit.
- A park requires an open draft PR whose description lists the blockers, and
  parked takes precedence over ready-pr.
- Because GateReeve PRs stay open drafts until merge authorization, ready-pr
  does not depend on draft state (spec A2).
