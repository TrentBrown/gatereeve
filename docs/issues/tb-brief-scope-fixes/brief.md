# Brief - tb-brief-scope-fixes

Closes #156 and #157. Light rigor; goal autonomy granted by the human for this
run.

## Goal

The light-brief scope comparison (`briefScope` in `delegation.js`) and its
documentation agree with each other and with how Markdown renders a brief:

1. (#156) The header comment above `briefScope` states the current blank-line
   rule: in prose a blank line counts as a block separator, a run of blank
   lines counts as one, and blank lines at the start or end are ignored. It no
   longer says blank lines in prose are ignored.
2. (#157) Two whitespace-significant constructs are no longer collapsed:
   - raw HTML `<pre>`, `<textarea>`, `<script>` and `<style>` content: from a
     prose line that opens one of these tags (outside inline code spans) to the
     line that closes it, or to the end of the brief when it is never closed,
     lines compare verbatim. Changing spaces inside a `<pre>` block therefore
     changes the scope. Which lines are headings, and so where the findings log
     starts and ends, is unchanged;
   - hard line breaks: a prose line (not a heading) ending in two or more
     spaces, followed by a line that is neither blank nor a heading, keeps a
     break marker. Adding or removing a hard break changes the scope; changing
     the number of trailing spaces, or trailing spaces before a blank line, a
     heading or the end of the brief, does not.
   A brief with none of these tags, no HTML comment and no trailing double
   space compares exactly as before. Detection fails closed, as #157 allows:
   text that only looks like an opening tag or comment (for example in a link
   destination, a comment spread over several lines of a paragraph, or a code
   span wrapped across lines) may make nearby prose compare verbatim, so a
   whitespace edit there needs re-authorization. A change to rendered `<pre>`
   content or to a hard break must never compare equal.
3. PROTOCOL.md describes both constructs alongside the existing rule.

## Findings log

- 2026-11-26: Run started light, raised to goal autonomy on the human's grant
  relayed by the coordinating thread.
- 2026-11-26: #157 fits a small change: both constructs are handled inside the
  existing line classifier, and each is covered by a focused assertion.
  Detecting the tag anywhere in a prose line, not only at its start, fails
  closed: an inline `<pre>` in a paragraph also compares verbatim.
- 2026-11-26: Raw HTML only makes lines verbatim; it does not hide headings.
  Hiding them would let an unclosed `<pre>` added to the findings log swallow
  the sections after it into the log, so their edits would stop counting.
  Fence tracking is likewise unchanged. A hard break is marked before any
  non-blank, non-heading line (a list item or fence included), which is
  stricter than rendering but never looser.
- 2026-11-27: Boundary review rounds 1-4 found successive edge cases. Each
  fail-open case (a later change compared equal) was fixed with a test:
  closing tags after a length-changing case fold, an indented tag continuing a
  paragraph, a tag after an unclosed inline comment. Fail-closed cases where
  plain text shows a tag (indented or fenced code, comments, escapes) were also
  fixed. The remaining cases need text that only looks like markup in rarer
  positions. Matching CommonMark exactly would need a full inline parser,
  which is not a small change, so the Goal now states the fail-closed
  contract instead of promising that every other result is unchanged.
