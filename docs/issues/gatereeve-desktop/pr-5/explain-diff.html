Background

Beginner's model: a journal plus a pinned rulebook

GateReeve does not store “the current phase” in a convenient mutable field. It stores an append-only event journal and pins the workflow model that gives those events meaning. The canonical observer combines them into a projection: feature state, slices, PR-boundary attempts, gates, blockers, actions, and artifacts.

Pinned modelstates, transitions, authorities
→
Event journalpassages and gate outcomes
→
Canonical observersnapshot plus named detail reads
→
DesktopDOM presentation only

Earlier PRs established this contract and the Electron shell. This PR fills that shell with the complete observational experience. The crucial constraint remains: Desktop may explain a command and copy it, but it cannot invoke GateReeve transitions or launch an agent.

Three kinds of information

Governed stateProjection, gates, evidence, artifacts, and actions come from the canonical observer.
Source contextLocal, Git, and GitHub observations enrich the view independently and can degrade independently.
Session contextCheckpoints and handoffs help an agent resume, but they never count as evidence or authorize passage.
The governing rule: visual convenience must never create a second interpretation of workflow state.

Intuition

Think of Desktop as the instrument panel in front of a mechanical interlock. The panel can show every latch, explain why one is closed, and hand you the exact operating instruction. The panel itself does not defeat the interlock.

A concrete example

Suppose a gate says PASS, but one of its inputs has changed. The canonical snapshot reports the outcome and freshness separately. Desktop renders both. It does not simplify this to a reassuring green card, and it does not rerun the gate. Likewise, ordinary uncommitted source code is activity, while an uncommitted journal or pinned model is a governance warning.

Code walkthrough

1. The overview projects, it does not infer

renderer.js receives a validated snapshot and builds the feature rail, milestones, slices, attempt selector, gate cards, warnings, and action cards. The rail order is loaded from the pinned model detail. Gate cards preserve dependency IDs and separate outcome from freshness. Action cards retain the canonical authority, inputs, reasons, readiness, and copy command.

snapshot + pinned model detail
  → feature rail and milestones
  → slice and attempt selection
  → gate dependencies and evidence links
  → governed action explanation + copy only

2. Detail stays lazy and named

The initial snapshot is compact. Artifacts, the complete journal, exact attempt JSON, and the full model graph load only when requested. Each request names a contract kind and canonical ID. There is no arbitrary path reader.

RendererreadDetail("artifact", id)
→
IPC validatorexact kind and bounded ID
→
Canonical observerallow-listed named result

3. Four viewers, one trusted exception

Markdown becomes a small semantic DOM built from text nodes. JSON and JSONL use the observer's structured value. Plain text stays text. The trusted explain-diff document is the deliberate exception: a dedicated gatereeve-artifact: protocol serves only the currently selected canonical HTML artifact, unchanged, in a separate-origin frame.

markdown → safe text-node DOM
json/jsonl → structured pretty print
text → preformatted text
html → gatereeve-artifact://desktop/<encoded canonical artifact ID>

4. Session is a side channel, not evidence

session-observer.js discovers exactly CHECKPOINT.md, .checkpoints/*.md, and regular files under .handoffs/. It rejects symlinks, paths outside the chosen worktree, oversized files, unknown IDs, and non-Markdown checkpoint archives. The renderer labels the view non-authoritative and refreshes its inventory independently of the journal.

Checkpoint / handoffresume or transfer context
→
Session viewread-only, exact ID
≠
Gate evidencereadiness and passage

5. The package boundary remains narrow

The preload and main process add Session reads and clipboard copy, but no transition or command execution channel. The visual fixture imports production renderer code for browser inspection, while the package files allow-list excludes visual and test assets. The final dry-run contains 46 intended runtime files.

Important edge cases

Clean CI checkoutSession can be empty. The canonical integration test now accepts both populated local context and the correct empty state.
Symlinked contextA symlinked file or allow-listed directory is omitted; a realpath outside the selected worktree is never read.
Model mismatchDesktop shows incompatibility or read-only migration impact. It never silently applies the bundled model.
Remote outageGitHub status becomes incomplete without erasing the valid local projection or Git observation.
Small windowAt 760x560, navigation stays available, the page becomes one column, and split viewers stack without horizontal body overflow.
Trusted HTMLThe document is intentionally not sanitized or sandboxed; selection is constrained by canonical artifact identity and a dedicated origin.
