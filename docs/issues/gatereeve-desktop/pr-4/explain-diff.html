Background

The beginner's model: state is not a collection of Markdown files

A GateReeve feature has an append-only event journal and a pinned workflow model. The current state—designing, planning, implementing a slice, waiting at a PR boundary—is a projection of those durable inputs. Artifacts such as spec.md and verification.md supply evidence, but a user interface must not infer a competing state from filenames.

→

Desktop rendererpresents; never governs

PR #2 established that observer contract. PR #4 does not replay the journal again. It packages an exact staged copy and calls the same observer used by the plugin and Commander surface.

The narrower problem solved here

An Electron renderer is intentionally unprivileged. It cannot read the filesystem or invoke Node. The main process can, but exposing its power broadly would turn a friendly observer into an alternate workflow engine. The change therefore needs two things at once:

A narrow waistOnly named reads and benign OS actions may cross IPC.
Live observationLocal, Git, and GitHub knowledge arrive independently and can fail independently.
Limited memoryOnly worktree recents and window geometry survive an app restart.
Predictable scopeThe user chooses one worktree; there is no machine-wide discovery scan.

Intuition

Think of the application as a telescope. The telescope remembers where you last pointed it, but it does not keep yesterday's sky and call it current. Each refresh begins with the nearby, trustworthy observation and then adds distant information.

1. Select/work/feature
→
2. Local nowjournal, pinned model, artifacts
→
3. Gitbranch, head, dirtiness classes
→
4. GitHubPR and checks, or unavailable
Remote failure is incompleteness, not invalidity. If GitHub is offline, the already validated local snapshot remains useful. The GitHub source says unavailable; it does not erase the feature state.

A toy example

{
  "mode": "governed",
  "featureId": "gatereeve-desktop",
  "active": { "sliceId": "desktop-shell-observation" },
  "sources": {
    "local":  { "status": "current" },
    "git":    { "status": "current" },
    "github": { "status": "unavailable", "detail": "offline" }
  }
}

The source statuses tell the truth independently. A later GitHub success causes another canonical projection with richer facts; there is still only one interpretation of workflow state.

Code walkthrough

1. A self-contained package, not a CLI wrapper

apps/desktop has its own package metadata, main process, sandboxed preload, renderer, shared contracts, resources, and tests. The staging helper now accepts a validated consumer manifest name and include list. Desktop takes the exact protocol plus the two context-resolution Python helpers; runtime code has no import from cli/ and no qp-cli-core dependency.

2. The read-only IPC waist

Renderer requestMain-process constraintWhat is absent
Choose or reopen worktreeAbsolute existing directory; recent paths must be in preferencesNo global scan
RefreshNo arguments; canonical recomputationNo transition execution
Read detailKind is artifact/events/attempt/model; IDs are validatedNo arbitrary path reader
Open or reveal artifactID must resolve to a safe, existing artifact in the current snapshotNo arbitrary shell command or URL

Every request must come from the exact top-level gatereeve-app://desktop/index.html frame. Outputs are checked again with the canonical snapshot/detail validators before crossing back.

3. A coordinator with generation tokens

Selection and refresh are asynchronous. Without coordination, a slow response from worktree A could arrive after the user selected worktree B. Each operation increments a generation. Results publish only while their token still matches:

const token = ++generation;
const context = await protocol.resolve(worktreePath);
if (token !== generation) return false;
// publish only for the still-current selection

The same rule retires stale Git and GitHub responses. The renderer receives local state immediately, while refreshing remains true until enrichment settles.

4. Events locally; a timer only remotely

The watcher observes the selected feature directory and its known first-level packet directories. Bursts are debounced into one full recomputation. GitHub uses a 60-second interval only when the last reliable result says the PR is open or a check is pending. A transient remote error does not cancel an already justified poll. A merge or terminal checks do.

Focused windowFocus triggers full refresh.
Minimized windowGitHub timer continues; it has no visibility condition.
Closed appWatcher and timer are closed; there is no service.

5. Preferences are deliberately boring

The one JSON file has four fields: schema version, recents, last worktree, and window geometry. Writes use a temporary file, atomic rename, and a serialization queue. Invalid paths and undersized geometry are discarded. Snapshot, artifact, remote, and governance data never enter it.

6. A minimal but real shell

The renderer supplies explicit selection, recent paths, refresh, mode, feature state, active slice, and independent sources. It uses native buttons, a live status region, visible focus, the 760×560 minimum, and GateReeve's purple/indigo language. The richer state rail, gate graph, viewers, history, model, and notifications remain later slices rather than being simulated here.

Edge cases and boundaries

Missing feature homeThe canonical snapshot reports missing; Desktop does not initialize it.
Legacy recordDesktop reports legacy; it does not adopt it.
Half-written governanceA lock without journal, or pending migration, reports inconsistent.
Unsupported pinned modelThe observer reports incompatible; the bundled model does not reinterpret history.
Ordinary source workIt is activity, distinct from dirty journal or model governance warnings.
CLI uninstalledDesktop still reads its packaged canonical core directly.
This PR establishes the shell and observation machinery. Native launch evidence on macOS and supported Ubuntu hosts belongs to the hardening slice; this NUC lacks one Electron GUI library, so the boundary records that check as pending instead of manufacturing success.
