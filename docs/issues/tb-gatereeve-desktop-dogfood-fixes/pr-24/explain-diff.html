From approved Cask to installed proof

PR #24 records the last operational half of GateReeve's rc.2 delivery: the approved Homebrew Cask became public, passed both architecture paths, upgraded the user's Mac, and proved the corrected application behaviors in the installed notarized build.

Contents: Background · Intuition · Evidence walkthrough · Quiz

Background

A release can be correctly built and notarized yet still fail its users at the distribution boundary. A Cask might name the wrong digest, an Intel runner might expose a packaging fault, or the installed app might inherit a different process environment from a terminal. That last distinction is especially important for the Python discovery fix that started this feature.

Earlier slices established the product implementation, the coordinated rc.2 package, Apple trust, and the exact Cask publication plan. PR #24 does not rebuild any of them. It records what happened when those immutable inputs crossed the public Homebrew boundary.

Key distinction: package evidence proves what was produced; installation evidence proves what users actually receive and observe.

Evidence walkthrough

1. The publication record becomes complete

The Cask record moves from prepared to published. It preserves the approved plan digest, exact generated Cask digest, public tap pull request, merge commit, and a completed receipt. A post-publication dry run confirms that recovery sees the public surface as already complete.

Each tracked JSON result binds the observed app to the release version, bundle identifier, Developer ID authority, Gatekeeper result, DMG digest, and expected universal binaries.

3. The real Mac proves the user transition

The maintainer upgraded through the public tap from rc.1 to rc.2. Homebrew replaced the application, strict deep code-signing verification passed, and Gatekeeper reported source=Notarized Developer ID. The installed app then launched normally.

4. Dogfooding closes the behavior loop

In a live PortReeve workflow, the Homebrew-installed app found Python 3.14.7, rendered the larger branded masthead, kept the Setup sidebar stable, refreshed artifacts without losing reading state, rendered inline Markdown correctly, and confined external, relative, and fragment links to their intended destinations.

What this PR changes: audit evidence and workflow state only. Product code is unchanged, and the final P10 whole-feature evaluation remains separate.
