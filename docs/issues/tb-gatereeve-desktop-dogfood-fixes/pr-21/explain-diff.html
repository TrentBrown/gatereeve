Background

Why preparation and publication are separate

Apple trust transforms application bytes. The release pipeline therefore builds a candidate from an immutable commit, signs it with Developer ID, submits it for notarization, staples Apple's ticket, and verifies the resulting DMG on both Apple Silicon and Intel. Only those final bytes may become the release artifact.

The important boundary: approving the protected Apple job only released credentials to a read-only preparation run. It did not create a tag, GitHub release, marketplace update, website change, or Homebrew mutation.

Intuition

Think of the release record as a sealed packing list. It names the source, every output, every checksum, and every required public destination. The packing list is useful before shipment: reviewers can prove that the box is correct without sending it anywhere.

The sealed identity

source = 1b7c7e519c90a13d140f59c65e0304bb78000753
version = 0.1.0-rc.2
dmg.sha256 = ec50610dfbeffe9bf0004f313e1413ae6d62c58a88cc3b0fa2c25b30b280754f

The dry run checks the shipping route while keeping every destination in the pending state. A later command must present the exact plan digest and explicit approval before it can mutate those destinations.
