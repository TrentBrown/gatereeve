Background

The two states a reader must not confuse

GateReeve presents a governed workflow state, such as Delivering Slices, and a separate inspection selection. A reader may select Designing to reread design.md while the workflow remains in delivery. The selection changes the hierarchy being inspected; it must never rewrite the meaning of current workflow guidance.

Governed current stateAuthoritative protocol projection: DELIVERING_SLICES
Inspection selectionReader chooses DESIGNING to inspect an older artifact
Current guidanceStill derives from DELIVERING_SLICES

Why the old overview became noisy

The overview used several visually strong surfaces at once: runtime error, setup readiness, mode diagnostic, warning stack, source boxes, a permanent Attention card, and permanent Next Actions. Their semantic boundaries were unclear. A routine dirty source tree could receive a colored notice near a genuine incompatible-record failure.

Intuition: severity and ownership are different questions

The change asks two questions for each condition. First, is it important enough to interrupt the whole workflow overview? Second, which object owns the detail? Only workflow-wide exceptions reach the consolidated alert. Everything else is placed beside its owner.

Global exceptionObserver failure, inconsistent or incompatible record, suspension, uncommitted journal/model governance inputs.
Object-local conditionA failed or stale gate, blocked action, or incomplete Setup prerequisite stays on that object.
Routine contextSource changes and unavailable enrichment remain quiet inside Sources.
Toy exampleA dirty application source file is useful context, but it does not prevent workflow passage. An uncommitted event journal changes governance evidence. The former belongs in Sources; the latter deserves the overview alert.

Code walkthrough

1. One pure alert policy

globalAlert collects a runtime error, a governed-mode diagnostic, and non-activity warnings. It discards activity warnings, removes duplicates, and returns one presentation model with a title, tone, and item list.

if (warning.severity === 'activity') continue;
const items = [...new Set(messages)];
return { title, tone, items };

Because the policy is pure, the unit test can cover ordinary activity, repeated governance warnings, incompatible mode, and runtime failure without launching Electron.

2. The overview loses duplicate surfaces

The markup now has one role="alert". Sources move into a native disclosure under the project context. The Attention section disappears. Current workflow guidance starts hidden and is rendered only when the canonical snapshot actually proposes actions.

3. Conditions follow their owners

Gate reasons and blocker messages render inside the gate card. Setup incompleteness changes the header control to Setup · Needs attention while the detailed remediation remains in Setup. Action reasons, required inputs, authority, and copyable command stay inside the expanded action disclosure.

4. Guidance cannot drift with inspection

The hierarchy still reads workspaceState().selectedFeatureState to decide which subordinate cards to show. Guidance does not. It reads snapshot.projection.feature.state, so selecting Designing cannot make delivery guidance masquerade as design guidance.

elements['guidance-context'].textContent =
  `Current: ${humanize(snapshot.projection.feature.state)}`;

5. The fixture becomes a matrix

The Electron-free visual fixture accepts a scenario query parameter. Its eight cases cover routine source activity, governance warnings, suspension, inconsistent and incompatible modes, observer failure, no actions, and a blocked gate. This makes visual review repeatable without a package or deployment cycle.
