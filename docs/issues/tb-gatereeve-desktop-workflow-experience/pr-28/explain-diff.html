Background

GateReeve is an observer over a governed feature record. It reads a canonical snapshot and presents what the workflow says; the Desktop UI must never turn a click, a tab, or a project switch into workflow mutation.

Electron in three layers

Main process

Owns the native window, application menu, project coordinator, and narrowly validated IPC endpoints.

Preload bridge

Exposes an allow-listed API into a sandboxed renderer. It validates messages at the process boundary.

Renderer

Owns visual selection and session-only workspace state. It reads snapshots and named artifacts but cannot advance the protocol.

What existed before

The Desktop already had trusted project admission, a persistent ordered project registry, active-only observation, safe artifact readers, and a functional long-form workflow page. Its navigation and detail presentation were still linear: one left navigation column, one central page, and embedded viewers inside individual sections.

The structural problemA project is the root of a working context, but the old layout treated project identity, application navigation, workflow hierarchy, and artifact detail as siblings. That made later progressive disclosure difficult and encouraged multiple detail viewers.

Code walkthrough

1. The workspace store makes identity explicit

renderer/workspace-state.js centralizes each project's main view, hierarchy selections, panel geometry, ordered tabs, and active tab. Opening and closing become deterministic state transitions rather than scattered DOM side effects.

document:design.md
gate:slice-attempt-1:judge

close(activeIndex) → tabs[min(activeIndex, lastIndex)]

2. The HTML becomes an application shell

The masthead now holds Setup, version, refresh, and panel controls. Beneath it, the grid has three independent regions: the saved-project sidebar, a central workspace with fixed main tabs, and the docked inspector. Artifacts is reduced to an inventory.

3. Rendering reconciles open tabs with fresh snapshots

Every canonical refresh runs the open artifact tabs against the new inventory. A disappeared or unsafe document does not leave old content on screen: its tab becomes unavailable. Successful content refreshes preserve a reasonable scroll position, while stale async reads are rejected by sequence guards.

4. Native shortcuts remain push-only

The main process builds standard application-menu accelerators. Their callbacks send only toggle-sidebar or toggle-inspector through the preload bridge. The main process never asks for or stores the renderer's workspace state.

5. CSS constrains, rather than merely sizes, the inspector

The requested inspector width is clamped in state, then the grid caps the actual track to the space remaining after a 300px central workspace. This matters at the 940px supported window width: all three regions remain present without document-level horizontal overflow.

projects | minmax(300px, 1fr) | min(requested, remaining space)

Important edge cases

Same document, many doors

Deduplication uses canonical path, not the button or hierarchy context that opened it.

Same gate, two attempts

Virtual gate detail includes attempt identity, so historical and current attempts cannot overwrite each other.

Panel hidden

Visibility changes; tabs, active identity, and requested width remain intact.

Artifact disappears

The tab remains honest and useful, but content is replaced by an unavailable state instead of stale evidence.

Project removed

The coordinator removes only GateReeve's reference. The renderer discards only that project's in-memory workspace after success.

Small window

The central region keeps 300px, the inspector yields width, main tabs scroll locally, and the page itself does not overflow horizontally.
