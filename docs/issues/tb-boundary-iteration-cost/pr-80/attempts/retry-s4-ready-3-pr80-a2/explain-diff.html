Background

Start here: what a gate and a packet mean

A gate is a required check, such as verification or independent spec review. A packet retains the source identity and check evidence so a reviewer can inspect what was evaluated. Its manifest is an index: large source material is referenced and digest-bound rather than repeated in a single prompt.

The protocol reduces an append-only event journal into the feature state. A report in a directory cannot advance that state. The core must accept a result with the current inputs and prerequisite events. Human acceptance and actual merge remain separate events.

A fingerprint identifies the inputs to one check. A dependency binds to the actual preceding result event. If Verification is replaced, its dependent review must be refreshed even when the check has the same name.

Earlier slices delivered compact, history-blind review inputs, guarded completion recovery and advisory discovery. This slice connects those pieces to the repeat work at an existing PR: preparing context, starting an attempt, recording checks and publishing current evidence.

The checkpoint has a smaller job than the journal.

It remembers execution progress in worktree Git metadata. After interruption, the coordinator asks what the core actually recorded and what Git/GitHub currently contain. It cannot certify code, grant a waiver or authorize merge.

If the process stops just after the core records evt-retry-ready-3-verification, resumption finds that event, validates its inputs and bytes, and advances without duplicating it. If code changed, resumption reports remediation instead of treating that PASS as current.

Two kinds of change

Evidence-only commit: the trusted synchronization check confirms every change belongs to declared evidence and the pinned code is unchanged. Existing formal freshness rules govern that same attempt.

Code or requirement change: fix and review the defect class, declare revised readiness and begin a fresh attempt. Old formal PASS results are not copied.

Early spec/code review remains useful on failing iterations. Explain Diff, final narrative and consolidated summaries wait for current nonblocking substantive checks and triage.
