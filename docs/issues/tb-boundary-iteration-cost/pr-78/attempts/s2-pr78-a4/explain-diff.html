Background

A short introduction to the workflow

A feature has approved requirements, a plan and a journal. Delivery slices implement parts of the feature and each receives verification, independent review and human acceptance before merge. The journal records those events so the protocol can decide which action is allowed next.

The code being merged and the evidence explaining it have different roles. A boundary packet binds reports to a pinned source range and lists their content hashes. Its manifest is small; supporting reports and files remain separate references. A source commit can receive additional evidence without changing the reviewed implementation, provided deterministic checks prove that only declared evidence changed.

Slice review and whole-feature review have different scope. A feature can have every slice merged while lacking a final review that accounts for the complete approved rubric. The previous route to Finalizing relied on a normal feature-final merge. Relabeling an old slice merge or recording a generic transition would misrepresent that history.

This recovery path applies when the last actual boundary was slice-scoped and all delivery is resolved. It requires an explicit applicable whole-feature Judge waiver plus the remaining whole-feature verification, spec assessment and retention evidence. A true feature-final merge keeps its existing path.

Intuition

Imagine a story feature delivered in two accepted merges. Its assembled code is commit C, and its approved requirements have identity Q. The user waived the whole-feature Judge for that feature at C with Q. Recovery must verify those exact identities and all remaining obligations before it can record a new event.

1 · Delivering SlicesEvery delivery is merged or abandoned. Accepted merge provenance identifies the complete source C.
2 · Validate recoveryBound approval text, source C, requirements Q, full verification/spec evidence and retention agree.
3 · FinalizingAppend one dedicated event. Existing configured modules must pass before Complete.
A short human answer needs concrete context.

“Waive the Judge” can use the approval prompt actually shown to the user. That bound prompt must identify whole-feature scope, the feature, integrated commit and approved requirement identity. Agent-authored report fields alone do not establish that applicability. Preserve an ambiguous historical record and reconcile its applicability.

A preflight reads and checks these materials without appending. The mutation freshly validates and appends a dedicated FEATURE_FINALIZATION_RECOVERED event. Repeating the same recovery ID and bound request reconciles that event; a conflicting request is rejected.

Code

Read-only preparation and verified mutation

recovery.js resolves the configured feature and original base, checks the selected source against integration history, derives approved spec/design identities from Git and verifies every accepted merge at both its recorded merge and the assembled source. It loads digest-bound reports, verifies actual confirmation text and safe evidence files, checks retention, and appends only after the configured guard passes.

TRACKED retention includes ignored untracked records in the cleanliness check and independently proves index membership for every bound report, confirmation and supporting file. File hashes establish content; Git tracking establishes retention.

A durable receipt and shared contract

recovery-contract.js validates whole-feature report shape, source/requirements authority and permitted dispositions. Preparation and replay share safe relative-path and SHA-256 reference validation. The receipt retains the exact four report references and binds its canonical request identity to them.

Replay reads durable journal data; it does not reinterpret later changes to supporting files. Actor labels record cooperative observations and do not authenticate a person.

State passage and compatibility

projection.js accepts the dedicated event only with valid receipt/provenance and resolved authorized delivery. finalization.js recognizes its verified source anchor while retaining all normal module requirements. Generic transitions cannot manufacture recovery or use a slice review’s feature-final flag to skip obligations.

Model 1.6/core 1.2 introduces this path. Older locks remain readable and require explicit compatible adoption before recovery becomes available. The plugin-local adapter exposes both operations; the CLI is an optional wrapper. Codex and Claude consume the same canonical contract.
