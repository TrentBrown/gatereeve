Background

Start here: what a formal boundary proves

A delivery branch contains code and its specification. Before a human reviews it, verification checks the implementation, a Judge independently checks compliance, and other gates review code, patterns and decisions. A packet keeps each artifact bound to the exact Git source. The source hash matters because a passing review of yesterday’s code says little about today’s changes.

A packet does not authorize a merge. Human review and authorization of the exact reviewed final head remain separate requirements.

The old builder collected the complete patch, including encoded binary changes, in one JSON value before moving it into files. It rejected an aggregate packet over 12 MiB. It also supplied decision journals and prior reports through documents and the repository snapshot. Those records helped explain the implementation, but could influence an independent judgment.

The new formal Judge still runs after full Verification. This slice changes how evidence reaches it; advisory readiness, completion recovery and retry orchestration arrive in later slices.

Intuition

Think of the manifest as a reading map. It contains exact source identities and references. Each reference names immutable bytes and their digest. A large patch remains complete on disk, while the initial prompt stays small.

1 · Pin sourcebase + head + scope + rubric IDs
2 · Export materialtext chunks, inventories, binary blobs
3 · Filter snapshotapproved requirements, source, current Verification
4 · Fresh Judgeread-only context, no inherited turns
5 · Host receiptverdict + source/view audit retained afterward

Text example

A 24 MiB patch becomes an index of chunks no larger than 64 KiB. Ordered offsets let the host verify that their combined bytes equal the original exported patch.

Binary example

A modified image has an old blob and a new blob, each accessible through a hashed file reference. The text patch names the change without encoding the same binary material inline.

If feature and final-slice patches have identical bytes, both references point to one payload. If they differ, both ranges remain available. Compaction never changes the selected Git range to fit a size limit.

Build referenced inputs

Expose exact source, with permitted evidence

pinned-snapshot.js bypasses archive export attributes and validates every allowed file’s bytes, executable mode and symlink identity against Git. It copies bound evidence, checks hashes and lengths, removes temporary object databases, and makes the snapshot read-only. Source aliases or symlinks exposing excluded history block preparation.

agent-workflow-service.js selects the compact builder only for opted-in definitions. It retains the full Verification dependency. Current linked images/PDFs require explicit bound attachments, copied into a reserved evidence area with unambiguous names. Legacy capture scripts, Ruby casks and source/configuration files remain inspectable.

Keep adoption and result coverage explicit

Judge 3 selects compact-review-v1 under model 1.5/core 1.1. Definitions without that declaration keep legacy construction. Older feature locks do not migrate when installed code changes. The new validator binds the host audit outside the Judge’s view and rejects results that omit, duplicate or invent declared criterion IDs.

Whole-feature review must include the complete approved rubric, alongside the complete assembled source and the focused final-slice range. Source/module resources are registered in the inventory and staged into CLI/Desktop packages.
