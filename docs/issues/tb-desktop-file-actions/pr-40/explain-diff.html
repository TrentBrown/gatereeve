GateReeve Desktop · PR #40

From “Open” to a bounded file-action menu

This change turns the artifact viewer’s single-purpose Open control into a split button that can open, reveal, copy, save, and locate a canonical workflow artifact—without giving the renderer arbitrary filesystem or process authority.

Background

The beginner’s map

An Electron application has two important security domains. The renderer draws HTML and handles clicks. The main process can reach the filesystem, operating-system dialogs, Finder, and external applications. A preload bridge and exact IPC messages connect them.

RendererChooses an artifact ID and a bounded action.
Preload + contractsReject malformed or overly broad requests.
Main processResolves the canonical path and performs the native operation.

GateReeve already inventories workflow artifacts such as spec.md, tracker.md, and per-PR evidence. The renderer never needs to invent a path: it sends an inventory ID, and the coordinator resolves the trusted absolute path.

The narrow problem

The old header offered a plain Open button plus Finder and path-copy actions. The desired experience needs several related verbs and a remembered default, while still behaving honestly on a local desktop: “Save to Downloads” is a copy, not a cloud download.

Intuition

Think of the control as two layers. The large side repeats the preferred action. The disclosure side explains and changes that preference while exposing less frequent operations.

Utilities

Copy path

For example, selecting VS Code both opens spec.md and remembers vscode. The next primary click sends { artifactId: "spec", editorId: null }; the main process interprets null as the stored preference. Choosing an application through the native dialog is deliberately one-time and does not expand the renderer contract.

Key invariant. An application path such as /Applications/Visual Studio Code.app never crosses from renderer to main. Only a catalog ID such as vscode does.

Code walkthrough

1. A main-process service owns native behavior

artifact-actions.js contains a fixed editor catalog, detection under the system and user Applications folders, an atomic preference store, source-preserving copy operations, and GitHub URL derivation. The GitHub link is accepted only when Git proves the file is tracked, the origin is GitHub, and HEAD is a full commit SHA.

Renderer: openArtifact("spec", "vscode", true)
                    ↓ validate exact shape
Main: coordinator.artifact("spec").absolutePath
                    ↓ match fixed editor catalog
/usr/bin/open -a "/Applications/Visual Studio Code.app" canonicalPath

2. Exact contracts replace a generic opener

The shared contracts and preload bridge add named methods for capabilities, opening, choosing an application, Save As, Downloads, and GitHub. IPC resolves every artifact through the coordinator before calling the service. This is more repetitive than a generic “execute file action” call, but its authority is visible and testable.

3. The renderer builds a capability-driven split menu

The renderer requests artifact content and action capabilities together. It lists detected editors, omits GitHub when provenance cannot be established, updates the primary button’s accessible label after an explicit choice, closes the menu after selection, and translates rejected promises into the existing toast.

4. The browser fixture simulates the native boundary

The fixture uses the production renderer and styles. Native calls append visible events to a fixture console, and “Fail next action” lets a reviewer inspect error feedback in a browser. The service, IPC, contracts, and renderer remain covered by the desktop test suite.

Edge cases and review outcome

  • A canceled chooser or Save As dialog returns false and produces no success toast.
  • An unavailable remembered editor falls back to the OS default.
  • Downloads chooses a numbered filename instead of replacing an existing file.
  • A non-GitHub remote, untracked file, or invalid commit removes the GitHub action.
  • An initial artifact load failure still renders a safe fallback action menu and recovery message.
Residual manual check. The headless Linux host cannot exercise Finder, Launch Services, macOS application bundles, or native dialogs. The automated contract is green; these integrations should be smoke-tested on the laptop after merge.
