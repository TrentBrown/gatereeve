Background

The product has two different jobs

The GateReeve Plugin governs work: it records durable workflow state and enforces passage. GateReeve Desktop observes that record. Desktop is optional, read-only, and useful only when the Plugin has created something to observe. The earlier slices made its observer self-contained and added Setup and compatibility; this slice turns the source application into a Mac product.

Before this PR

Developers could run Electron from the repository. The app had no permanent native bundle identity, approved shipping icon, installable DMG, or proof that packaged bytes behaved like source.

After this PR

A macOS host can derive an iconset, build one ARM-plus-Intel app, seal an ad-hoc candidate, place it beside an Applications shortcut, and verify the emitted DMG on both native architectures.

Rolling Vale supplies the visual identity: two towers, a pale arch, a raised portcullis, rolling hills, and a light road that continues through the threshold. The reviewed source image is not merely copied by convention; its SHA-256 digest is part of the package contract.

Trust boundary. This PR makes an ad-hoc signed development candidate. That proves bundle integrity without claiming Developer ID trust. Signing, notarization, stapling, Gatekeeper acceptance, and public distribution remain later protected work.

Intuition

The central idea is to treat packaging as a small compiler pipeline. Each phase has one input and one inspectable output. The last two phases use the same DMG rather than two separately built approximations.

Universal apparm64 + x86_64 in one bundle
DMGApp + /Applications link
Two native runsOne downloaded artifact

Suppose the build emitted D. A weaker test would build D-arm on one host and D-intel on another. Both might pass while differing in resources or behavior. This PR instead uploads D once. The two jobs download that artifact, mount it read-only, inspect it, and launch it natively. The equality is an artifact fact, not an assumption.

build(macOS ARM host) → D
download(D, ARM host) → inspect + run
download(D, Intel host) → inspect + run

Code walkthrough

1. One permanent identity contract

macos-package-contract.mjs centralizes the product name, bundle identifier, Electron version, universal architecture, volume name, icon source, icon digest, required ASAR files, and packager options. Tests pin the values. Drift fails before a build can quietly produce a differently named product.

2. A positive staging boundary

package-macos.mjs does not copy the whole Desktop project and try to remove dangerous pieces afterward. It copies five known runtime directories and one known image into a clean stage, then writes a dependency-free package manifest. This keeps Python, test fixtures, visual tooling, package scripts, and external Node modules out by construction.

3. Native asset and bundle construction

generate-macos-icon.mjs invokes fixed Apple tools to create the standard 16-through-1024-pixel iconset and compile GateReeve.icns. Electron Packager then builds architecture universal and applies an ad-hoc seal. create-macos-dmg.mjs copies the app with ditto, creates a literal Applications link, builds a compressed image, and asks hdiutil to verify it.

4. Verification starts from the deliverable

verify-macos-package.mjs starts with the DMG, not the staging tree. It mounts read-only, checks plist identity and icon declaration, runs lipo over the app, Electron framework, and helpers, verifies the deep ad-hoc signature, inventories ASAR, and then launches the packaged executable with isolated preferences and a Finder-like PATH.

QuestionEvidence
Is this really GateReeve?Bundle name, display name, ID, version, icon, and source digest.
Is it really universal?Every principal executable must contain exactly arm64 and x86_64.
Is it self-contained?Required ASAR files exist; Python and development directories do not.
Can a user install it conventionally?The mounted DMG contains GateReeve.app and a symlink to /Applications.
Does the deliverable run?The mounted app observes a real governed fixture on both native host types.

What passed

The package job emitted a 243,571,641-byte DMG with SHA-256 fc3c007d…7fe4a. GitHub stored it as artifact ID 9661075538. Both native jobs downloaded the same artifact digest, then independently reported successful verification on arm64 and x64. The 61-test Desktop suite and every existing Ubuntu, container, contract, and source-runtime job also passed.

What has not been claimed: the DMG is not a public release and is not Gatekeeper-trusted. The next release slices must add a coordinated release record, Apple credentials and protected signing, update discovery, explicit publication approval, and finally the Cask.
