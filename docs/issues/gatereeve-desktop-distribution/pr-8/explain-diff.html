GateReeve learns to explain whether it is ready

This slice adds a persistent, read-only Setup surface. It observes the tools and agent-native Plugins a user selected, compares exact Desktop/Plugin release pairs, and gives useful next steps without becoming an installer.

Background

GateReeve has three surfaces with deliberately different jobs. The Plugin governs workflow passage. The optional Commander CLI gives another control and inspection surface over the same protocol. Desktop observes the durable record and makes it understandable. PR #8 does not blur those boundaries.

Plugin

Required for governing new or active work. Installed and managed by Codex or Claude Code.

Desktop

Optional visual observer. It reads state and now reports setup readiness, but never advances the workflow.

CLI

Optional Commander.js surface. Desktop does not call it and does not require it to exist.

Why Setup belongs in the observer

A readable feature record can outlive the environment that created it. That creates two distinct questions: “Can I inspect this historical record?” and “Is this machine ready to govern new work?” Before this PR, Desktop answered the first question but had no durable place to answer the second.

Key distinction: incomplete setup blocks the claim that active work is operationally ready. It does not hide a safely readable existing record.

Why version equality is too strict—and version ranges are too loose

Desktop and Plugin are released together, but native managers can update them at different times. Exact equality would reject harmless, tested skew. A broad semantic-version range would claim compatibility without proof. The chosen middle ground is an explicit table of tested pairs.

Matched
Same coordinated release
Compatible
Different, explicitly tested releases
Incompatible
No exact evidence for this pair

A concrete example

Desktop: 0.1.0
Selected agents: ["codex", "claude"]

Codex:
  authenticated: true
  Plugin: 0.1.0-rc.2 (explicitly compatible)

Claude Code:
  executable: missing

Shared prerequisites: all present

Result: READY through Codex
        Claude Code still needs attention

The “at least one” rule matters. Selecting Claude as a second intended environment must not make a functioning Codex environment unusable. Equally, Setup must not erase the incomplete Claude selection merely to make the headline green.

Freedom inside a deterministic boundary: agents can work through any selected ready host, while GateReeve states exactly which hosts are ready and why.

Facts versus actions

Detection runs fixed read-only commands such as version, authentication status, and plugin listing. Remediation commands are data rendered in a code block. Clicking “Copy native command” writes text to the clipboard; it does not execute the text.

Code walkthrough

1. The state contract becomes explicit

shared/contracts.js adds exact schemas for selected agents, shared prerequisites, per-agent CLI state, Plugin state, compatibility, and remediation. The Desktop envelope requires preference selection and Setup selection to agree. A ready state requires all shared prerequisites and at least one ready selected agent.

operationalReady =
  prerequisites.every(item => item.status === 'present')
  && agents.some(agent => agent.status === 'ready')

2. Compatibility becomes project data

shared/setup-compatibility.json records the Desktop version and exact tested Plugin pairs. main/setup-compatibility.js validates the shape, prevents duplicate pairs, and rejects contradictory labels. Lookup is exact: an absent pair is incompatible.

3. Native adapters observe their owners

main/setup-observer.js discovers only selected agents and the shared prerequisites. Codex and Claude Code retain ownership of their Plugins. Detection prefers structured JSON, keeps bounded text fallback, and distinguishes an unavailable manager from a confirmed missing Plugin.

Fail closed: an enabled Plugin with no manager-reported exact version is incompatible. A failed listing is unavailable. Neither becomes operationally ready by guesswork.

4. Finder launch no longer means terminal PATH

main/executable-discovery.js extends macOS discovery with fixed Homebrew and user-manager locations, the Codex application resource directory, and bounded enumeration under the NVM version root. It does not crawl the home directory or the filesystem.

5. Coordination persists intent, not detection

main/preferences.js persists the explicit agent selection. main/coordinator.js rechecks at launch and on request. Version, authentication, and Plugin facts stay ephemeral. When the selection changes, stale detection cards are cleared before the new check begins.

6. IPC and the renderer expose a narrow surface

The preload adds only recheckSetup and setSelectedAgents. The renderer provides first-launch Setup, permanent Setup navigation, copy-only native commands and official links, visible compatibility evidence, and a historical/offline banner. It never receives a general command runner.

7. Tests bind the promises together

The suite covers exact pair classification, malformed metadata, selected-only probing, manager failures, unknown versions, native remediation, one-of-two readiness, selection changes, first-launch rendering, mixed ready/incomplete rendering, package contents, accessibility, and real Electron startup on macOS and Ubuntu.

Edge cases the design makes visible

No selection

Setup is unconfigured. No agent installation is examined and Recheck is disabled until the user chooses.

Listing failed

The Plugin is “unavailable,” not “missing.” A failed observation cannot prove absence.

Version omitted

An enabled Plugin without an exact manager-reported version cannot prove a tested pair and fails closed.

Compatible skew

Work can continue, evidence is shown, and the native update path is offered as copy-only guidance.

One of two works

Overall setup is ready through the working agent, while the incomplete selected agent remains visible.

Old record, broken setup

The record remains readable under an explicit historical/offline label; readiness is not overstated.
