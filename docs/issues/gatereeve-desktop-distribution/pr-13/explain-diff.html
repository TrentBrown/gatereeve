GateReeve engineering note

Logs are not data

PR #13 gives the signed macOS package a clean machine-readable result channel.

BackgroundIntuitionCodeQuiz

Background

Electron Packager reports useful progress while it builds the x64 and ARM64 slices. GateReeve's packaging command also prints a final JSON object containing the application path, DMG path, size, checksum, and version. Both used stdout.

The protected workflow redirected stdout into a file and assumed the entire file was JSON. The second rehearsal showed why that assumption was false: signing completed, but the file began with “Packaging app…” and JSON parsing stopped before notarization.

Intuition

A terminal transcript is for people; an interchange file is for programs. They may describe the same operation, but they should not share framing rules. The fix adds a named result destination rather than guessing where JSON begins inside a transcript.

progress → ordinary process output → CI log
result   → --result-file PATH    → strict JSON consumer
Compatibility: callers that omit --result-file still receive final JSON on stdout, exactly as before.

Code

One result emitter

emitPackageResult serializes the result once. With a result path it creates the parent directory and writes the file. Otherwise it writes to the supplied stream or process stdout.

An opt-in CLI contract

The command validates --result-file like its existing arguments and emits only after packaging and signing return successfully.

A deterministic workflow consumer

The trust job supplies the result path directly. Electron's progress remains visible in Actions, while the following step reads a file whose only permitted content is the final JSON document.

Regression tests

Tests prove the dedicated file is valid JSON, its parent can be created, selected-file mode does not use the output stream, legacy stdout JSON remains valid, and the workflow cannot return to shell redirection.
