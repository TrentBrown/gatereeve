Background

The beginner's version

An Electron application contains Chromium for rendering and Node.js APIs for trusted operating-system work. That does not mean it inherits the same environment as a terminal. When macOS Finder starts an application, shell startup files are not consulted and familiar commands may not be on PATH.

GateReeve Desktop reads a durable feature record. Before it can read that record, it must answer two questions: which workspace did the user select, and where does that workspace keep the feature record? The old implementation delegated those questions to a bundled Python script. It worked in a source checkout but made Python an undeclared prerequisite for an installed app.

The relevant architecture

The protocol source under plugin-src/shared/resources/protocol is canonical. Plugin packages, the optional Commander CLI, and Desktop stage or import that source. This matters: a Desktop-only replacement would solve packaging today while creating three subtly different notions of “the current feature” tomorrow.

Invariant: there is still one context contract. The Python resolver remains temporarily as a migration oracle and for existing workflow tooling, while JavaScript becomes the shared protocol implementation used by Desktop.

Intuition

The key move is to separate canonical local evidence from optional enrichment. Reading .agentic-workflow.json and the journal is local application work. Git adds repository facts. gh adds pull request facts. Failure in the outer rings must not erase the inner ring.

Code walkthrough

1. The protocol owns context resolution

context.js now implements the complete configured and legacy contract: safe identifiers, external task metadata, repository selection, full object IDs, symlink-aware containment, detached-HEAD rejection, and the stable result envelope. Configured mode reads files only; legacy mode uses the explicitly supplied Git executable because its feature identity is the current branch.

const configPath = await findWorkspaceConfig(start);
if (configPath === null) {
  return await legacyContext(start, { gitExecutable, environment, exec });
}
const repositories = await parseRepositories(raw.repositories, workspaceRoot, environment);

The parity suite deliberately asks both implementations the same questions: a nested multi-repository selection, explicit alias selection, legacy branch identity, a symlinked config, and unsafe configurations.

2. Desktop discovers executables without scanning

The discovery helper probes a bounded set: standard macOS locations, explicit PATH entries, or a narrow override. It verifies that a candidate is an executable file. It never walks arbitrary directories.

const fixedDirectories = platform === 'darwin'
  ? ['/usr/bin', '/opt/homebrew/bin', '/usr/local/bin']
  : [];
return unique([...fixedDirectories, ...pathDirectories]);

The exact paths are injected into context, Git, and GitHub observers. A missing path therefore becomes data rather than an accidental ENOENT from a bare command.

3. The Desktop projection drops Python scripts

Desktop now stages only protocol/. The two Python context support files disappear from its runtime resources. This does not remove the Plugin's trusted Python gate providers: Desktop observes persisted gate results but cannot execute workflow passage.

4. Runtime smoke observes a governed fixture

A small fixture builder creates a genuine initialized GateReeve record. Ubuntu 22.04, Ubuntu 24.04, and macOS CI launch Electron, open that record, require a governed snapshot, and wait until the renderer shows its exact feature identity.

Boundary of this PR: CI exercises the Electron source runtime. The universal packaging slice will reuse this contract against the exact application bundle and prove that no separate Node runtime is needed. R2 correctly remains NOT YET.
