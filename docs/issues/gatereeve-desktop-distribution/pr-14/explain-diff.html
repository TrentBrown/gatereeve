Background

The third protected rehearsal crossed the important boundary: Developer ID signing, Apple notarization, stapling, Gatekeeper assessment, upload, and credential cleanup all passed.

The failure happened afterward. The upload action received one file from the repository and another from the runner's temporary directory. GitHub found their common ancestor and preserved everything below it, creating two deep paths. The verification jobs expected the files at the artifact root.

Intuition

An artifact should expose its own deliberate layout, not the build machine's directory layout. The workflow now places both finished files in one staging directory before upload.

before: repository/…/GateReeve.dmg + runner-temp/apple-trust.json
after:  trusted-bundle/GateReeve.dmg + trusted-bundle/apple-trust.json
Identity is preserved: copying changes location, not bytes. The DMG checksum recorded by the accepted trust evidence remains authoritative.

Code

Trust first

Staging runs only after notarization, stapling, and Gatekeeper assessment succeed, so an incomplete candidate cannot enter the trusted artifact.

One fresh root

The exact versioned DMG and apple-trust.json are copied into one runner-temp directory. Uploading that directory yields the stable flat contract.

Consumers stay simple

ARM64 verification, Intel verification, and coordinated-record assembly retain the same explicit root-level filenames. They no longer know anything about repository or runner paths.

Guardrails stay intact

Credential cleanup remains unconditional, repository permissions remain read-only, and the workflow still cannot create a tag or release.
