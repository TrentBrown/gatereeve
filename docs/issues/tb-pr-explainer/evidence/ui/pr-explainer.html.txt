<section id="context"><h2>A document viewer with two kinds of content</h2><p>GateReeve Desktop observes governed software-workflow records. Its <strong>canonical artifacts</strong> are named documents from the trusted workflow snapshot: for example, a feature’s design or spec. <strong>Session Markdown</strong> shows supporting checkpoints and handoffs; it is marked non-authoritative. Both already call the same <code>renderMarkdown</code> function. Canonical artifacts pass navigation callbacks; Session does not.</p><p>This PR changes the rendering seam, rather than artifact loading or workflow state. The approved design asks a maintained parser to own Markdown grammar, leaving GateReeve’s trust and presentation rules in application code. <a href="https://github.com/TrentBrown/gatereeve/blob/faa30266bf0b60a03ac2285017762f76faf52b63/apps/desktop/renderer/renderer.js#L1366-L1373">Artifact call site</a> · <a href="https://github.com/TrentBrown/gatereeve/blob/faa30266bf0b60a03ac2285017762f76faf52b63/apps/desktop/renderer/renderer.js#L1653-L1661">Session call site</a> · <a href="https://github.com/TrentBrown/gatereeve/blob/faa30266bf0b60a03ac2285017762f76faf52b63/docs/issues/tb-desktop-markdown-rendering/design.md#L5-L34">Design intent</a></p>

<section id="mechanism"><h2>Parse broadly, then narrow the output</h2><p>The new module constructs real DOM nodes from syntax trees. It does not ask a library for an HTML string and insert it into the application. The intermediate representations are <strong>MDAST</strong> (Markdown structure) and <strong>HAST</strong> (HTML-shaped structure).</p>
<figure aria-labelledby="flow-caption"><ol class="flow"><li><div><strong>Parse Markdown + GFM</strong><span><code>remark-parse</code> and <code>remark-gfm</code> recognize syntax and retain source offsets.</span></div></li><li><div><strong>Preserve risky constructs as text</strong><span>Raw HTML, images, and reference images become text nodes using the original source slice. An image URL is still readable, but cannot become a loaded image.</span></div></li><li><div><strong>Convert to HAST and capture link intent</strong><span><code>remark-rehype</code> creates semantic structure. Ordinary link destinations move into temporary application metadata and lose their <code>href</code> before sanitizing.</span></div></li><li><div><strong>Sanitize against a narrow schema</strong><span>Allow headings, tables, lists, code, footnotes, and disabled checkboxes; omit resource-bearing image/media elements and arbitrary attributes.</span></div></li><li><div><strong>Construct DOM and apply product policy</strong><span><code>hast-util-to-dom</code> uses the supplied document. Post-processing adds heading IDs, wraps wide tables, disables tasks, and activates only accepted ordinary links.</span></div></li></ol><figcaption id="flow-caption">Source-grounded mechanism; no product execution is implied. <a href="https://github.com/TrentBrown/gatereeve/blob/faa30266bf0b60a03ac2285017762f76faf52b63/apps/desktop/renderer/markdown-source.js#L91-L141">Source transforms and processor</a> · <a href="https://github.com/TrentBrown/gatereeve/blob/faa30266bf0b60a03ac2285017762f76faf52b63/apps/desktop/renderer/markdown-source.js#L228-L275">DOM construction and policy</a></figcaption></figure>

<div class="grid"><div><h3>Visibility before filtering</h3><p><code>&lt;script&gt;…&lt;/script&gt;</code> and <code>![diagram](https://…)</code> become literal source before conversion. This preserves meaningful content without creating executable or resource-loading nodes. Unsupported parse/conversion failures fall back to the entire normalized source as a text node.</p><p class="ref"><a href="https://github.com/TrentBrown/gatereeve/blob/faa30266bf0b60a03ac2285017762f76faf52b63/apps/desktop/renderer/markdown-source.js#L74-L110">Exact-source preservation</a> · <a href="https://github.com/TrentBrown/gatereeve/blob/faa30266bf0b60a03ac2285017762f76faf52b63/apps/desktop/renderer/markdown-source.js#L238-L265">Conversion and fallback</a></p></div><div><h3>Contain wide content locally</h3><p>Tables receive a named scroll region; CSS keeps tables and code locally scrollable and distinguishes all six heading levels. <section id="links"><h2>Grammar support does not grant navigation</h2><p>The parser now recognizes more link forms, including reference links and autolinks. The same caller-owned resolver still decides whether an ordinary link becomes interactive. Rejected targets are replaced by their original Markdown source; accepted anchors use <code>href="#"</code>, prevent default navigation, and invoke the existing activation callback.</p>

<h3>Logical fragments survive physical ID prefixes</h3><p>A visible heading such as <code>## **Rubric**</code> gets physical ID <code>gatereeve-md-heading-rubric</code> and <code>data-markdown-fragment="rubric"</code>. <section id="shipping"><h2>A new build input, a self-contained runtime</h2><p>The dependency tree is a build-time concern. Pinned Unified packages and <code>esbuild</code> produce <code>renderer/generated/markdown-renderer.js</code>, which <code>dom.js</code> imports. The generated directory is ignored; the source tree must build it before use.</p>
<div class="grid"><div class="card"><h3>Source entry points</h3><p><code>pretest</code>, <code>prepack</code>, and <code>start</code> build the renderer. The renderer-only visual fixture now documents an explicit build prerequisite. The bundler emits ESM targeting ES2022 with no source map.</p><p class="ref"><a href="https://github.com/TrentBrown/gatereeve/blob/faa30266bf0b60a03ac2285017762f76faf52b63/apps/desktop/scripts/build-renderer.mjs#L15-L45">Bundle build</a> · <a href="https://github.com/TrentBrown/gatereeve/blob/faa30266bf0b60a03ac2285017762f76faf52b63/apps/desktop/package.json#L20-L42">Lifecycle hooks and pins</a></p></div><div class="card"><h3>Packaged entry point</h3><p>macOS staging calls the build directly, copies the bundle, and removes unbundled <code>markdown-source.js</code>. The ASAR contract requires the generated file. The staged application excludes the general <code>node_modules</code> tree.</p><p class="ref"><a href="https://github.com/TrentBrown/gatereeve/blob/faa30266bf0b60a03ac2285017762f76faf52b63/apps/desktop/scripts/package-macos.mjs#L31-L48">Staging build and removal</a> · <a href="https://github.com/TrentBrown/gatereeve/blob/faa30266bf0b60a03ac2285017762f76faf52b63/apps/desktop/scripts/macos-package-contract.mjs#L32-L46">Required ASAR paths</a></p></div></div>
<p>The neutral esbuild platform is deliberate: the build comment says the browser-conditioned character-entity dependency initializes a scratch element at import time. Keeping its deterministic table allows Node DOM tests to import the module before a fixture document exists. This is a build compatibility choice, not an additional renderer capability.</p>

<section id="reading"><h2>Read these seams closely</h2><p>The change is easiest to examine in policy order: preservation before sanitization, metadata before capability activation, then build inclusion. These concerns guide inspection; they are not an approval verdict.</p>
<div class="concern"><h3>Heading suffixes can overlap another heading’s own slug</h3><p>The code counts duplicates separately for each base slug. By source reasoning, headings <code>A</code>, <code>A</code>, and <code>A-2</code> can produce <code>a</code>, <code>a-2</code>, and <code>a-2</code> as logical fragments. That deserves inspection against the spec’s uniqueness requirement. The added heading test covers repeated identical slugs and formatting, but not this overlapping-suffix case. No product execution was used to confirm it.</p><p class="ref"><a href="https://github.com/TrentBrown/gatereeve/blob/faa30266bf0b60a03ac2285017762f76faf52b63/apps/desktop/renderer/markdown-source.js#L152-L161">Per-slug counter</a> · <a href="https://github.com/TrentBrown/gatereeve/blob/faa30266bf0b60a03ac2285017762f76faf52b63/apps/desktop/test/dom.test.js#L211-L233">Added heading test</a> · <a href="https://github.com/TrentBrown/gatereeve/blob/faa30266bf0b60a03ac2285017762f76faf52b63/docs/issues/tb-desktop-markdown-rendering/spec.md#L48-L52">AC5</a></p></div>
<div class="concern"><h3>Syntax correctness and renderer responsiveness have separate limits</h3><p><code>parse</code> and <code>runSync</code> run synchronously. The design explicitly calls out pathological documents blocking the renderer. The reported 718ms sample is useful context, but does not establish a resource bound or a latency limit for malformed/large input. <a href="https://github.com/TrentBrown/gatereeve/blob/faa30266bf0b60a03ac2285017762f76faf52b63/apps/desktop/renderer/markdown-source.js#L238-L239">Synchronous parse</a> · <a href="https://github.com/TrentBrown/gatereeve/blob/faa30266bf0b60a03ac2285017762f76faf52b63/docs/issues/tb-desktop-markdown-rendering/design.md#L116-L122">Design risk</a></p></div>
<div class="concern"><h3>Preserve semantics while narrowing attributes</h3><p>Footnotes need prefixed IDs, corrected <code>aria-describedby</code>, and local backreference handling. Tables need semantic cells plus local scrolling. Inspect these alongside the schema rather than reading the allow-list alone. Browser/screen-reader behavior is less directly established than DOM assertions because the captures and raw browser observations were not retained. <a href="https://github.com/TrentBrown/gatereeve/blob/faa30266bf0b60a03ac2285017762f76faf52b63/apps/desktop/renderer/markdown-source.js#L11-L72">Schema</a> · <a href="https://github.com/TrentBrown/gatereeve/blob/faa30266bf0b60a03ac2285017762f76faf52b63/apps/desktop/renderer/markdown-source.js#L176-L205">Footnote mapping</a></p></div>
