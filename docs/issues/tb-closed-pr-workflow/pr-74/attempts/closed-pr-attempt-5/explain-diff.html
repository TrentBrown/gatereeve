Background

New to GateReeve? Start here.

A branch holds the commits for a change. A pull request records which branch should be merged into which target. GateReeve adds a review process: it pins a specific commit, runs checks, evaluates the acceptance criteria, preserves reports, and asks a human to review that evidence before merging.

A review packet distinguishes the commit containing the implementation from later commits that contain only reports. A test result for one implementation should not silently authorize a different implementation. Currentness checks make changes to the source, PR identity, or repository preference visible.

The previous implementation offered two slice review mechanisms: a pull request or a synthetic candidate commit. Synthetic review introduced its own identity, publication, comment capture, and promotion path. This change removes that active path and its configuration switch. Existing historical records can still be decoded and validated.

The motivating constraint is the GitHub open-PR queue. Greg and Brad should not have to see work accumulating there during preparation. A closed PR retains its number and history, so the ordinary review packet can continue to refer to it.

Closed means absent from the open queue.

The PR remains on GitHub and can be opened directly. Creating it may still produce notifications, and there is a brief creation-to-closure interval.

Intuition

For a repository configured with the preference, imagine PR #74 at source commit A. Preparation creates it as a draft and closes it immediately. GateReeve then reviews A while PR #74 stays closed.

If the merge window fails, GateReeve closes the unmerged PR again. Preparation and review never reopen it just to satisfy a helper.

The frozen-diff wrinkle

The live experiment found that GitHub continues to report A after the branch advances to B while the PR is closed. Its native closed-PR diff also stays frozen. Reading that PR metadata alone would review the wrong commit.

GitHub PR #74Native reported head: A
Closed native diff: A
Remote branchCurrent head: B
Actual source to review
GateReeve contextEvaluated source: B
Reported head retained: A

The provider therefore resolves the live head branch and target branch. It retains the frozen reported values separately for audit. A missing live branch causes an error. At merge time, the reopened PR must match the exact head the human accepted.

Code

1. One repository preference

{
  "repositories": {
    "product": {
      "path": ".",
      "integrationBranch": "main",
      "keepPullRequestsClosed": true
    }
  }
}

This is an excerpt of repository configuration. The preference defaults to false when omitted, preserving normal open draft PR review. Both JavaScript and Python reject strings, integers, null, or other non-boolean values. Any old sliceBoundaryMode key produces guidance to remove it and use the new preference.

2. Preparation uses the exact PR

pr_lifecycle.py searches all states for the selected repository and head branch, then filters by target branch and excludes merged PRs. It reuses a unique matching unmerged PR, refuses ambiguity, or creates a draft. With the preference enabled, it verifies closure before resolving the pinned source context.

3. Review pins policy and live source

pr_context.py and boundary_context.py carry the preference into durable contexts. Currentness and finalization reject a policy change, a changed PR identity, a moved base, or an implementation change outside declared evidence paths. Closed PR snapshots use live remote refs and retain GitHub-reported refs. Review the packet or current branch comparison when the native PR diff is stale.

4. Authorization opens a short merge window

merge --context /tmp/pr-context.json \
  --reviewed-head <exact-accepted-final-head> \
  --authorization "Human approved this exact head" \
  --evidence-path docs/issues/<feature-id>

The helper validates policy, source, evidence and branch direction before reopening. Development branches are integration sinks and cannot be merge sources. After reopening, it verifies the native PR identity and head, marks the draft ready, waits for reported checks, checks the identity again, and requests a native merge with --match-head-commit. It uses no administrator bypass or automatic queued merge. A failed operation or interrupt triggers re-closure; a cleanup failure reports that the PR needs immediate attention.

5. Retire active synthetic operations

The synthetic publisher/comment/promoter helper and its active tests are removed. New synthetic boundaries and active synthetic currentness checks fail with migration guidance. The read-only historical context and packet validators remain, preserving prior evidence.
