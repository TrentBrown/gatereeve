Background

GateReeve already built one universal macOS DMG and coordinated it with the Plugin. It also signed, notarized, stapled, Gatekeeper-assessed, and checked the app on native runners. What it lacked was a strict authority boundary: the old preparation workflow accepted an arbitrary source ref, mixed trusted production with the publication environment, and had no durable hosted route for resuming an interrupted Apple request.

Product topology remains local

One Plugin candidate, one universal DMG, two native verification authorities, and a later linked Cask record.

Pluginuniversal DMGARM64Intel

Trust semantics converge

Reviewed-source pinning, exact-byte identities, separated credentials, request continuity, bounded recovery, create-once evidence, and publication-free rehearsal.

release-trustSHA-256request IDfail closed

Important boundary: this PR stops at desktop-trust-verified. It does not finalize distribution metadata, authorize publication, create releases, change Cask bytes, or move live secrets. Those are later governed steps.

Intuition

1. Trust production starts from one reviewed fact

The preparation workflow accepts only an RC tag. It checks out the dispatch SHA, proves the dispatch ref is main, fetches current origin/main, and requires all three commits to be identical. Every later job checks out that resolved SHA. Per-tag concurrency queues duplicate work rather than cancelling a run whose Apple history may already exist.

dispatch mainone input: RC tag
→
resolve SHAHEAD = dispatch = origin/main
→
protected trustread-only repository
→
native evidencesame SHA and DMG

2. “The DMG” is really two related byte identities

Apple receives the signed but unstapled DMG. Stapling intentionally derives the distributable DMG and may change its bytes. The new contract names both instead of pretending they must hash identically.

submitted DMGbound to attempt + Apple request
→
Acceptedsame request ID
→
copy + stapleauthorized trust derivation
→
final DMGbound to native proof + publication

Both identities and their lineage are retained for 30 days. Recovery always starts from the submitted bytes. Native verification and every future public action must use the final stapled bytes.

3. Recovery resumes evidence, not execution

A generic GitHub “re-run jobs” command can repeat signing or submission without knowing what the earlier runner accomplished. Both workflows therefore reject github.run_attempt != 1. The dedicated recovery dispatch downloads the retained attempt, submitted DMG, and signed app archive.

retained attemptprepared/submitted/timed-out/uncertain
→
history reconcileexactly one match
→
bounded polloriginal request only
→
finalize trustcopy, staple, assess

Zero or multiple history matches fail closed. Recovery receives the notarization key but no signing certificate, so it cannot rebuild or resign the candidate.

4. Two runners establish authority over one universal artifact

The universal DMG is verified separately on Apple Silicon and Intel. Each runner checks both binary slices, strict Developer ID facts, hardened runtime, timestamp, accepted request, staple, DMG Gatekeeper, mounted-app Gatekeeper, coordinated version, and real app smoke. Aggregation accepts exactly one create-once document from each architecture.

Rosetta is not Intel authority. A translated process is rejected. Apple's documented missing-key result means native execution and appears as empty output under the chosen CLI flags; unexpected output or an actual probe failure remains indeterminate and fails closed.

Code tour

The preparation and recovery workflows

coordinated-release-prepare.yml owns initial production. Apple secrets appear only on the steps that import or use them inside release-trust; the job has no write permission or publication command. Cleanup runs under always().

permissions:
  actions: read
  contents: read

concurrency:
  group: gatereeve-release-trust-${{ inputs.tag }}
  cancel-in-progress: false

environment:
  name: release-trust

coordinated-release-trust-recover.yml verifies the source SHA and approved workflow path for retained runs, restores GateReeve.app.tar without losing executable modes, reconciles uncertainty through notarytool history, and reruns native verification plus lifecycle construction.

Apple evidence records lineage

notarize-macos.mjs keeps the attempt bound to the submitted file. After acceptance it copies that file to the final path, staples and validates the copy, Gatekeeper-assesses it, and writes schema-v2 evidence once.

Native evidence is structured and aggregateable

native-trust-evidence-v2.js defines twelve required checks and exact source, candidate, artifact, request, runner, signature, and timestamp fields. The aggregate recomputes each document digest and insists on the set [arm64, x64].

const REQUIRED_CHECKS = [
  'dmgVerified', 'applicationIdentity', 'coordinatedVersion',
  'universalBinaries', 'strictDeveloperIdSignature',
  'hardenedRuntime', 'secureTimestamp', 'notarizationAccepted',
  'stapleValidated', 'dmgGatekeeperAccepted',
  'mountedApplicationGatekeeperAccepted', 'governedFixtureSmoke'
];

The trusted lifecycle ends exactly where this slice ends

trusted-release-lifecycle-v2.js revalidates Apple and native evidence, inventories the Plugin tree, and now verifies the Plugin’s own RELEASE.json before binding it. This matters during recovery: two RC tags may share one source commit, so source equality alone cannot prove candidate equality.

Review found and closed two exact-authority gaps

The first boundary attempt correctly failed. It found that recovery could select a Plugin artifact from another RC at the same source commit, and that an unexpected translation-probe failure was treated as native. Hosted CI then established the documented empty missing-key result on native Intel and found that the acceptance image omitted the new recovery workflow. The final head validates Plugin metadata, distinguishes native missing-key from real probe failure, and tests the recovery workflow inside both container images.

Reviewer focus

  1. Confirm only exact current reviewed main can start protected production.
  2. Confirm release-trust cannot publish and recovery cannot sign or rebuild.
  3. Confirm the submitted DMG remains the request authority while the final stapled DMG becomes the native/publication authority.
  4. Confirm uncertain submission never automatically resubmits and all retries are bounded.
  5. Confirm ARM64 and Intel evidence are complete, independent, non-Rosetta, create-once, and agree on exact bytes and request.
  6. Confirm the lifecycle stops before finalization/publication and keeps GateReeve’s universal topology.

Residual evidence: real Apple signing/notarization, GitHub runner labels, protected environment contents, and live native documents are deliberately deferred to the P9 nonpublishing rehearsal with a fresh RC.
