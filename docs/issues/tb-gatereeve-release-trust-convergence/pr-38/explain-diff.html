Background

A release system is trustworthy only if it can answer four questions: which source produced the artifact, which exact bytes Apple accepted, who authorized each privileged operation, and how an interrupted operation resumes without silently changing identity.

The implementation work landed earlier in PRs #32, #33, #34, and #37. It introduced schema-v2 lifecycle records, durable notarization attempts, protected signing, native architecture evidence, sealed publication plans, and linked Cask recovery. PR #38 is the last mile: it records what happened when those contracts met real GitHub environments and Apple infrastructure.

Topology stays GateReeve-shaped. One Plugin tree, one universal macOS DMG, and a separately approved Homebrew Cask. Conformance with PortReeve means shared trust semantics, not identical artifact graphs.
