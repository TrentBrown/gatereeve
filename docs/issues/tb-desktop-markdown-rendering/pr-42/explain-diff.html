Background

The broad view

Markdown is not a sequence of independent substitutions. Asterisks can open emphasis or remain literal; indentation changes list structure; reference definitions can affect links elsewhere; and fenced blocks suspend inline parsing. A parser must first build a tree that captures these relationships, then render that tree.

GateReeve displays trusted workflow artifacts and Session documents inside an Electron renderer. The content is local, but it is still data rather than application authority. A document must not create an image request, execute raw HTML, or smuggle an unsafe destination into the operating-system link handler.

The old seam

The previous renderer was a compact handwritten formatter. It handled the common cases the application originally needed, but every additional Markdown interaction made its regular expressions harder to reason about. Full tables, task lists, footnotes, reference links, nested structures, and CommonMark edge cases need an actual syntax tree.

Invariant retained: rendering text is allowed; granting a capability is a separate decision made by the existing application resolver.

Safe structure

Input:  ~~done~~
Tree:   delete → text("done")
DOM:    <del>done</del>

The syntax tree preserves meaning and produces semantic elements.

Unsafe capability

Input:  ![x](https://host/x.png)
Tree:   image + source offsets
DOM:    text("![x](https://host/x.png)")

The exact source remains visible, but no resource-loading element exists.

Links follow a similar two-key rule. Markdown may recognize a link, but the DOM receives an anchor only when the caller's resolver accepts its destination. A click then invokes the existing activator; rejected links revert to their exact source text.

Mermaid: a mermaid fence remains ordinary code.language-mermaid. It is readable and safely styled, but no diagram runtime or SVG is introduced in this PR.

Code walkthrough

1. One shared parser

renderer/markdown-source.js configures Unified with remark-parse, remark-gfm, remark-rehype, rehype-sanitize, and hast-util-to-dom. Both artifact and Session views continue to call the same renderMarkdown seam, so their language behavior cannot drift.

2. Source-preserving safety

Before conversion to HAST, raw-HTML and image nodes are replaced using their original source offsets. The sanitizer then admits only the semantic structures GateReeve needs. The final tree is converted directly to DOM nodes: artifact content never passes through an innerHTML insertion point.

3. Application-owned navigation

Headings receive deterministic, duplicate-aware IDs with an application prefix. Their logical Markdown fragments are retained separately for existing fragment lookup. Inline links, references, and autolinks all flow through the same resolver/activator capability boundary.

4. Reproducible delivery

scripts/build-renderer.mjs bundles the pinned pipeline into a self-contained generated module. Pretest, prepack, startup, staging, and package checks all build or require it. The shipped ASAR contains the bundle but neither node_modules nor the unbundled renderer source.

5. Broader behavior and presentation

Scoped styles cover six heading levels, nested lists, table containment, disabled tasks, footnotes, and wide code. Tests exercise representative CommonMark cases, GFM, hostile and malformed source, fragment behavior, link policy, both document surfaces, accessibility, staging, and packaging.
