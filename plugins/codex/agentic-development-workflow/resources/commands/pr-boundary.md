# Pr Boundary

Read `<plugin-root>/resources/PROTOCOL.md` for the current operation/input contract.

Prepare a pinned candidate from clean application source and current approved
requirements. Declare readiness explicitly; this launches no evaluator. Choose
the order of focused checks and independent reviews. `review` consumes actual
Verification and assesses code, every criterion, CI/local alternative scope,
project rules, material decisions and all relevant findings in each of two fresh provider contexts.
Use review.select and review.execute for the required pair; request additional review only when risk or uncertainty warrants it.
Context, packet and retention are checked automatically at their milestone.
Reuse qualifying proof or request targeted independent delta review covering
changed code and interactions. Preserve original failures and supported findings.
Pattern review is optional. Request its gate explicitly when active rules need a
dedicated assessment. Validate packet reference closure. `milestone.check/pass` acceptance enforces required proof or
scoped exceptions. In both rigors, run `review.publish` for the PR so its
description carries the current independent review summary for the candidate
head before presenting it. Once acceptance evidence qualifies, the operation
returns the pinned local HTML explainer and any configured Mutineer advisory.
Lead with the explainer link for human or agent review. If generation fails,
retry publication using the retained verification and review. Republish after
any new review or candidate. A closed PR may display its previous head. In that
case, GateReeve qualifies the pushed source branch and returns the local packet.
Publish the hosted summary when GitHub observes the reviewed head within the
authorized merge window. For opted-in repositories, Mutineer runs against
the pinned target only at this handoff. The local explainer and thread summary
link to the detailed Mutineer report retained in the acceptance packet. The
GitHub PR description carries the independent review summary and evidence
identifiers. Offer pruning separately when a maintainer requests it.
Present the exact candidate and risks for human acceptance unless an applicable recorded
standing acceptance grant already covers this work, or the run is delegated and
the candidate is a fully passing `SLICE` PR into the integration branch
(`delegation.apply`; PROTOCOL.md Delegated autonomy). A light run's tripwire hits
stop for the human under supervision.
Use `delivery.resume` to advance eligible steps under existing authority and reconnect work.
When all required gates PASS, `authorization.apply` can also be used with that grant's event
hash to record exact candidate acceptance. A standing grant never waives a gate.
Use configured PR closure policy; only reopen inside an explicitly authorized
protected merge. `merge.prepare` produces the action; `human.decide` records the
actual authorization, or `authorization.apply` derives the exact action from an
explicitly permitted standing merge grant. Acceptance-only permission cannot
merge. `merge.execute` rechecks gates, authority and the published summary before
execution. Slice PRs target the integration branch; the final PR runs from the
integration branch into the release branch. A release-branch merge needs a per-PR
human instruction ("merge #N") recorded as `authorize-merge` bound to that PR;
the agent then runs `merge.execute`. Standing grants never cover the release
branch. If GitHub refuses an authorized merge under a hosting rule, report the
`EXTERNAL_BLOCKER` to the human as an external blocker, not a gate failure, and
retry `merge.execute` after it is resolved. Deployment remains separately authorized. Open
drafts are default; closed drafts require explicit repository configuration. No automatic
remediation-round limit or evidence-commit requirement applies.

Autonomous authority may qualify eligible residual risk separately from original review outcomes. It is mandate-bound, never substitutes for a missing reviewer or mandatory verification, and never authorizes the final release merge.
